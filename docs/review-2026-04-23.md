## Critical

### [bug] assigned_member_id not scoped to current shop
`app/controllers/shop_admin/quotes_controller.rb` — `create` action
`app/controllers/shop_admin/jobs_controller.rb` — `issue_quote` action

`params[:assigned_member_id]` is used directly without verifying the member belongs to `current_shop`. A shop owner could craft a request to assign a member from a different shop.

```ruby
# fix
member = current_shop.shop_members.find(params[:assigned_member_id])
```

---

### [bug] Quote line rate/hours not validated — silent zero
`app/controllers/shop_admin/quotes_controller.rb` lines 19-20

`lp[:rate_nok].to_f` and `lp[:hours].to_f` silently return `0.0` on blank/nil params. A quote with zero rate passes model validation because `amount_ore = 0 * 0 = 0` which fails `greater_than: 0` on `QuoteLine` — but the error message may not surface properly if the rescue catches `RecordInvalid` and redirects with a generic message.

**Fix:** add explicit presence check before conversion.

---

### [bug] InvoicingService inconsistency: `amount_ore` used as `rate_ore`
`app/services/bookify/invoicing_service.rb` `build_work_lines`

When quote_lines exist, `BookingLine` is built with `rate_ore: ql.amount_ore`. But `amount_ore` is the **total** for the line (rate × hours), not the hourly rate. This creates a booking_line where `rate = total` and `hours = ql.hours`, so POP receives an amount that is `hours × total_amount` — a large overcharge.

**Fix:** pass `rate_ore: ql.rate_ore` and keep `total_hours: ql.hours`.

## High

### [security] No timeout in rake task HTTP calls (SSRF risk)
`lib/tasks/translations.rake` — `bmw_put` / `bmw_get`

`Net::HTTP` calls have no `open_timeout` or `read_timeout`. `BMW_SERVER` is taken from ENV without domain allowlist. If ENV is misconfigured or compromised, the app can make requests to internal network addresses.

**Fix:** mirror `bmw_backend.rb` — add `open_timeout: 3, read_timeout: 5`, validate that `URI(base_url).host` matches a known BMW domain.

---

### [bug] Race condition in AutoConfirmJob — no DB lock
`app/jobs/auto_confirm_job.rb`

Between `return unless job.pending_confirmation?` and `InvoicingService.new(job).call` the status could change (e.g. client confirms manually). `InvoicingService` would then try to invoice an already-invoiced job.

```ruby
# fix
job.with_lock do
  return unless job.pending_confirmation?
  return unless job.confirmation_deadline_at&.past?
  Bookify::InvoicingService.new(job).call
end
```

### [bug] JobMailer crashes if assigned_member or enrollment is nil
`app/mailers/job_mailer.rb` — `member_assigned`, `job_invoiced_member`

`job.assigned_member.enrollment.email` raises `NoMethodError` if `assigned_member` was removed between job creation and mail delivery (Sidekiq retries make this more likely).

**Fix:** guard with `.&` chain; discard the job if email is nil:
```ruby
email = job.assigned_member&.enrollment&.email
return if email.blank?
mail(to: email, ...)
```

### [bug] QuoteLine `calculate_amount` uses `.to_i` losing precision
`app/models/quote_line.rb` line 14

```ruby
self.amount_ore = (rate_ore.to_i * hours.to_f).round
```

`rate_ore.to_i` truncates. If `rate_ore` is stored as decimal (e.g. `95.5`), the result is off. Use `rate_ore.to_f`.

### [ui-ux] Shops-selected count in skill_pages/show doesn't update
`app/views/skill_pages/show.html.haml` line 41

```haml
= t("skill_pages.show.shops_selected", count: 0)
```

The Rails `t()` renders once at page load with `count: 0`. As the user checks boxes, the Stimulus controller updates the `<span>` with just the number, but the surrounding pluralized string ("butikker valgt") stays "0 butikker valgt" forever.

**Fix:** move the full label text into the Stimulus controller using `data-` values:
```haml
data: { one: t("skill_pages.show.shops_selected", count: 1),
        other: t("skill_pages.show.shops_selected", count: 2) }
```
Then interpolate in JS.

## Medium

### [bug] work_hours has no upper bound
`app/controllers/shop_admin/jobs_controller.rb` and `clients/jobs_controller.rb`

`params[:work_hours].to_f` has no max. Submitting `work_hours=99999` results in a booking for 99999 hours sent to POP.

**Fix:** clamp: `hours = params[:work_hours].presence&.to_f&.clamp(0.5, 24.0) || 8.0`

### [bug] Client can override shop's work_hours on confirmation
`app/controllers/clients/jobs_controller.rb` `mark_complete`

The client's confirmation form accepts `work_hours` and `work_date` params and recalculates `work_amount_ore`. This means the client can change the invoiced amount unilaterally after the shop marked complete. No validation against the shop-agreed amount.

**Fix:** use the shop-set values by default; only allow client to confirm, not change amounts. Or add a maximum deviation check.

### [bug] BRREG lookup race condition on registration
`app/controllers/clients/registrations_controller.rb`

Two concurrent requests with the same `org_number` both pass BRREG lookup, then both attempt `@client.save`. The unique index catches the second, but the error message shown is the generic Rails uniqueness error, not the BRREG result.

**Fix:** add `rescue ActiveRecord::RecordNotUnique` and return a clear "already registered" message.

### [bug] BeMyWords backend calls during request cycle if cache is cold
`lib/i18n/bmw_backend.rb`

If `Rails.cache` is cold (e.g. after restart), the first web request triggers `eager_load!` which makes 18 sequential HTTP calls to BeMyWords (9 namespaces × 2 locales) with a 5s read timeout each — potentially 90s of blocking. In production this means the first request times out.

**Fix:** move the BMW fetch to an initializer background thread or a Sidekiq job on boot, rather than lazy `eager_load!`. Keep YAML as the immediate source, and overlay BMW asynchronously.

---

### [perf] N+1 in freelancer dashboard
`app/views/freelancer/dashboard/show.html.haml`

`@bookify_shops.each` iterates shops from `@bookify_jobs.map(&:shop).uniq`, then `@bookify_jobs.select { |j| j.shop_id == shop.id }` re-scans the full job array for each shop — O(shops × jobs) in Ruby.

**Fix:** group in the controller:
```ruby
@jobs_by_shop = @bookify_jobs.group_by(&:shop_id)
```

### [bug] BRREG backend unreachable blocks registration
`app/services/brreg_service.rb`

If `data.brreg.no` is unavailable (timeout, 5xx), `BrregService` returns `success: false` and the client cannot register at all. There's no retry or fallback.

**Fix:** distinguish between "invalid org" (reject) and "lookup failed" (allow with `verified_at: nil`, flag for re-check). Add a `brreg_check_failed_at` column so admins can see which registrations need manual follow-up.

### [bug] Domain constraint regex is case-sensitive
`config/initializers/domain_constraints.rb`

HTTP spec says hostnames are case-insensitive. `/\Abookify\./` won't match `Bookify.app`. Unlikely in practice but worth fixing.

**Fix:** add `/i` flag.

### [bug] `rake translations:refresh` references constant before require
`lib/tasks/translations.rake`

`I18n::Backend::BeMyWords::NAMESPACES` is referenced in the `refresh` task, but the backend class is only required via `config/initializers/i18n.rb` — not in the rake context unless `:environment` is loaded. The `:environment` dependency is included, so this should work, but it's fragile. If the initializer changes the require path, rake breaks silently.

**Fix:** add `require Rails.root.join("lib/i18n/bmw_backend")` at the top of the rake file.
