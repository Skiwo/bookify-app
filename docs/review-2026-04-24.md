# Code Review — 2026-04-24 (round 2)

Issues from round 1 (review-2026-04-23.md) are already fixed.

## Critical

### [security] shop_owner callback trusts shop_id from params
`app/controllers/bookify/callbacks_controller.rb` — `shop_owner`

POP redirects to `/bookify/callbacks/shop?worker_id=X&status=approved&shop_id=Y`.
`shop_id` is an attacker-controlled URL param. If authenticated, any shop owner
can craft a redirect with another shop's `shop_id` and overwrite its `pop_worker_id`.

**Fix:** don't trust `shop_id` from params — look up the shop by `current_user` instead.
Requires `require_authentication!` on the action.

## High

### [bug] Freelancer mark_complete missing hours clamp
`app/controllers/freelancer/jobs_controller.rb`

Shop admin and client controllers got `.clamp(0.5, 24.0)` in round 1, freelancer version was missed.
A freelancer can submit `work_hours=99999`, inflating the invoice.

---

### [bug] Dispute resolve!/close! allow invalid state transitions
`app/models/dispute.rb`

`resolve!` sets `job.status = :accepted` unconditionally. If the job is already
`:invoiced`, this reverts it to `:accepted` — potentially allowing a second invoice.
`close!` has no state guard either.

---

## Medium

### [ui-ux] Shop owner re-entering POP onboarding if already enrolled
`app/controllers/bookify/onboarding_controller.rb` — `shop` action

If `shop.pop_worker_id` is already set (owner already enrolled), visiting
`/bookify/onboarding/shop` redirects them to POP onboarding again — confusing UX.

---

### [bug] Client quote accept has no lock — concurrent double-accept possible
`app/controllers/clients/quotes_controller.rb` — `accept`

Two simultaneous requests both pass `.quoted` scope and `quote_expired?` check,
both update status to `:accepted` and post system messages.
Low probability in practice but worth guarding.

## Notes

- **pop_lines overcharge false alarm** — `rate: ql.amount_ore / 100.0, quantity: 1`
  is correct. POP calculates `rate × quantity`, not `rate × work_hours`.
  `work_hours` is payslip metadata only. This is consistent with the non-quote-lines
  path that already works in production.

- **Freelancer dashboard N+1** — agent flagged this but `.includes(:shop)` is
  already on the query at line 35. Not an issue.

- **JWT callback expiry** — POP is a trusted internal service; JWT validation
  in callbacks is over-engineering for this stage.
